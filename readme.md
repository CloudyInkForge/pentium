# readme.md（人看）

## 项目目标

用 AI 完成杂志 HTML 排版，由人类/CI 用 PeachPDF 转 PDF。AI 只负责 HTML 排版、目录/图片标签生成，以及 PDF 只读校验；不生成、不修改、不转换 PDF。

## 目录与文件

- `PP/peachpdf.exe`：仅人类/CI 使用，AI 禁止调用。
- 每期一个 4 位编号目录，如 `2611/`，存放该期同名 HTML 和内容。
- `src/`：原始数据，含 `descriptor.txt`。
- `articles/`：文章 txt；`content.txt` 统计名称、字数、栏目。
- `photos/`：图片；`phototags.txt` 记录所属文章、尺寸、字数、概要。
- `template/`：封面与内容页模板，HTML 必须据此构建。

## AI 权限

AI 仅有以下三项权力，且仅在明确要求时执行：

1. **HTML 排版设计**：创建/修改指定期同名 HTML，必须基于模板；仅可改版式相关文字，不得改正文事实、标题、作者、页码。
2. **目录/标签生成**：维护 `articles/content.txt`、`photos/phototags.txt`。
3. **PDF 只读校验**：用 `C:\Python313\python.exe` + `PyPDF2` 读取既有 PDF 的页数、页面尺寸、文本。只读，不写回、不生成、不转换、不删除。

### 禁止

- 禁止创建/修改/转换/删除/移动 PDF；禁止调用 PeachPDF；禁止安装 PDF 库。
- 禁止整理原始数据到文章；禁止构建其他索引；禁止写其他文件。
- 禁止擅自改变模板页尺寸、边距、栏数、正文区高度、行高、栏宽、页脚机制。
- 禁止自动多栏平衡、自动分页、自动避让代替人工逐行核算。
- 禁止用固定高 `overflow:hidden` 裁切正文冒充分页。
- 禁止正文流内放大图替代“绝对定位图 + 洞”。
- 禁止绝对定位图/附记/装饰覆盖正文而不挖洞。

## 排版硬性规则（人检查清单）

1. **模板优先**：文章页必须沿用模板三栏固定正文区；不得改成双栏或自动平衡多栏。
2. **逐行核算**：每页占用行数 = 正文 + 洞 + 空行 + 图注预留；必须 ≤ 容量 − 6 行。不足余地必须移段、移图或分页。
3. **分栏切分必须钉死**：`.body` 必须带 `column-fill:auto`，每个分栏起点元素带 `.cbrk`（break-before:column）。浏览器与 PeachPDF 的行进位有 ±1–2 行差异，不钉死切分点，每栏容量与切分就会失控。**每页 `.cbrk` 个数必须 = 栏数 − 1**：连续两个 `.cbrk` 会强开第四栏，其后内容整段被裁且无任何报错（2611 期 P01 第 12–15 条曾整段消失）。
4. **页脚留白**：正文、图片、图注、附记、版权不得进入页脚区域。
5. **栏内图必须用流内图块**：图与图注同属一个 `.photo-block`（break-inside:avoid，块宽=图宽，窄图居中），随文排。禁止"绝对定位图 + 洞"机制——PeachPDF 行进位漂移会让图、图注与正文互相叠压，甚至整行正文被图盖住。
6. **图片样式完整**：`.ph` 必须有 `width:100%`、`height`、`background-size:cover`、`background-position:center`、`background-repeat:no-repeat`、`position:relative`。
7. **目录绝对定位**：`.toc-col/.toc2-col` 必须 `position:relative`；版权/索引/引文不得与 `.folio` 重叠。
8. **PeachPDF 兼容**：颜色全 `device-cmyk`；无透明度调浅、无 filter、无 grid 主布局、无 JS、无外链资源；图片只本地路径。
9. **PDF 只读核对**：转换后只读检查页数、页面尺寸、页脚文本、末页附记文本；发现版式问题只改 HTML。PDF 文本提取的"行数"会并行/漏行，只可用于栏底坐标与文本存在性核对，**不得用于换行预测**。

## 验证流程

1. AI 交付 HTML 前，必须先做**同字体浏览器逐页实测**（`agent.md` §2.6）：PeachPDF 嵌入 SimSun，本机浏览器回退栈同样命中 SimSun；实测规律是**浏览器每栏比 PeachPDF 多排 1–5 行（更保守）**，故"浏览器无溢出 + 非末栏 ≥2 行、末栏 ≥6 行余量"即 PDF 必然安全。逐元素取 `getClientRects()` 按栏归类，查每栏底余量与横向溢出（第四栏 = 有内容被裁）。
2. AI 交付 HTML，不碰 PDF。
3. 人类/CI 用 PeachPDF 转换。
4. AI 用只读脚本核对 PDF 文本与页面尺寸；必要时人工目检渲染结果。
5. 转换后必须逐页目检四件事：图注是否紧贴图下、图/图注/正文有无互相叠压（尤其正文行是否被图盖住）、**各栏末行是否完整显示（无半行/无整段缺失）**、页底留白是否均匀。
6. 若转换报错或版式异常，AI 只修 HTML，不修 PDF。
7. 终端任务必须及时；超时立刻停止，不安装 PDF 库。

## 常见失败（必须避免）

- 把模板三栏改成双栏自动流，导致行数容量估算失效。
- **用"绝对定位图 + 洞"机制排栏内图**：PeachPDF 与浏览器的行进位差 ±1–2 行（换行/取整差异，无法用标记消除），图与图注必然和正文互相叠压，甚至整行正文被图盖住（隐性丢字）。一律用流内图块。
- **漏掉分栏切分标记（`column-fill:auto` + `.cbrk`）**：各栏装哪些元素随引擎漂移，容量与切分失控。
- **连续两个 `.cbrk`（2611 期 P01 实证）**：第二个 `.cbrk` 强开第四栏，其后正文落入溢出列被 `overflow:hidden` 裁掉，不报错、肉眼难察（一篇文章的 4 个条目整段消失）。每页 `.cbrk` 数 = 栏数 − 1。
- **拆段调平后旧 `.cbrk` 未摘除（2611 期 P55 实证）**：前栏尾段下移后，旧栏起点钉点若在图块之后而未被摘除，该段起跳两栏，其后整段被裁。摘除时必须向后扫描到第一个带 `.cbrk` 的元素，不能只看紧邻元素。
- **前栏满溢 + 后栏 `.cbrk`（2611 期 P09/P14/P29/P34 实证）**：一栏溢出 1–2 行，后栏起点的 `.cbrk` 元素整体跳栏。切点没把握时改用自然流拆段（`p` + `p.cont`，不带 cbrk），段落跨栏续排对两端引擎差异免疫。
- **信 PDF 提取的行数核算（2611 期 P01 实证）**：按 BT 块统计的行数比真实换行少 40+ 行，导致"已满/已校准"的误判。换行预测只信同字体浏览器实测（`agent.md` §2.6）。
- **近满页加字号**：行数随字号反增，P01 提到 9.4pt 即溢出 22 行。余量 <10% 的页只可用图高/行距杠杆。
- 流内大竖图触发 PeachPDF 多栏跳栏，第一栏剩余空间浪费。
- 绝对定位的附记/装饰覆盖正文。
- `.body` 无固定高度、`.page` 固定高 `overflow:hidden`，正文被裁切。
- 未给页脚预留 `margin-bottom`，正文压页脚。
- 目录列漏 `position:relative`，引文/版权跑到页面左下并压页脚。
- `.endfig .ph` 漏 cover/position，末页图片异常、角标错位。
- 未逐行核算、未逐页目检、未只读核对就交付。
